Reuse locked dependencies, Pillow and private ClamAV processing; no search service, SPA, provider or new production dependency is proposed.

## 2. Scope, decisions and publication policy boundary

### Chosen approach and rejected alternatives

Use persisted, minimal PostgreSQL projections plus current source authorization at consumption. A pure live aggregate over private models on every search would avoid projection lag but create expensive/unbounded joins and accidental field exposure. An index-only authorization model would be faster but unsafe on revocation/expiry. External search, CDN-authoritative visibility and a second ACL system are rejected by the approved architecture and privacy requirements.

Professionals remains the publication source of truth. Marketplace can hide/remove derived output but cannot grant verification, rewrite private setup or publish on behalf of an owner. Assets checks a server-issued, current source-domain release through composition, not a caller's `is_public` or arbitrary subject UUID. Governance moderation owns the decision/history; composition applies the professional/post hide state without governance importing professionals/marketplace.

### Explicit public field allowlist

`PublicProfessionalDTO` contains only public profile UUID and canonical slug; deliberately selected display name, biography, specialties, declared experience (labeled self-declared), service modes, stored languages, broad country/region/city and mode tuples, safe accent/welcome text; selected current verified role badges; intentionally selected qualification summaries; eligible media delivery IDs/URLs, and published educational-post excerpts/links. Card and comparison DTOs are narrower views of this same contract, never independent model serializers. Missing experience stays unknown. No zero review/rating placeholder or structured rating is emitted.

`PublicCredentialSummary` contains role, title, issuer, type label and optional issue/expiry dates from an exact selected current qualification revision. It is not a document and not a claim that self-declared experience/specialties were certified. Only a role in the intersection of release-selected roles and fresh `verified_roles` may contribute summaries/badges/search/filter facts. Identity evidence, private identity name, birth date, phone, User UUID, credential/revision/evidence IDs, hashes, keys, staff notes, pending/rejected roles and internal reason codes are excluded. Public professional UUID is the profile ID, not an account directory.

Locations use existing broad active city/region facts only; never precise address/map coordinates. No baseline or athlete-derived personalization is read in C04. Optional filters supported now are selected specialty, stored language and self-declared experience; athlete goals require explicit user-entered specialty criteria rather than reading private baseline. Rating/review count, package characteristics, real acceptance capacity and consultation filters remain absent until their authoritative domains exist.

### Deliberate publication and consent

Approved authority: Product §§5–6 requires intentional public fields/media; architecture §8 and ADR-004 authorize separate sanitized copies only after source-domain publication authorization and consent checks. These authorize a professional's deliberate publication workflow, not reuse of athlete health/case-study consent. C03 explicitly defers public copies to C04.

Proposed engineering mechanism for approval with this plan: a versioned `ProfessionalPublication` and immutable `PublicationRevision`/release confirmation owned by professionals. A revision freezes the allowlisted payload, source profile version, selected roles, exact selected qualification revisions and media bindings; the owner sees the exact public preview and explicitly confirms public audience and the downloadable-copy limitation. Confirmation is false by default. A command uses current AccountActor, exact owned profile, expected publication/profile version and operation ID; verification alone never publishes. Optional explicit release expiry is supported, with no invented mandatory legal duration. Publish/unpublish and confirmation history are metadata audited; full content snapshots remain protected domain records under central retention.

This is the source-domain record of publication authorization required by ADR-004, not a general consent/ACL engine. Do not repurpose `baseline_storage`, `case_study`, self-grantee Consent or a private media grant as public-audience consent; existing Consent has participant/grantee/expiry semantics unsuitable for pretending “public” is a User. No new governance Consent purpose or implicit grantee is needed. Exact informed Persian wording, rights/third-party-image handling and operational privacy approval are release sign-offs already required by C03; synthetic engineering tests may use explicitly marked versioned test wording. If review determines that actual wording or a necessary media/consent category is not authorized, record it as a blocking decision before implementing that category; do not infer approval from a green test or enable it live.

Only own avatar/cover/logo and new own educational-image assets may feed public media. No credential/identity evidence, athlete image, progress photo, health record, reused case-study content or third-party private asset can enter this workflow. No credential-document publication endpoint is necessary or authorized. A separate future requirement to publish documents needs its own policy/design review.

Lifecycle: draft → publication_requested → published, with owner unpublished, staff hidden, expired and source-stale denial states. A public revision becomes effective only when current source approval and all selected copies are ready. Source edits change the compared source version and suppress the old release until explicit renewed confirmation; no delayed worker publishes new private text automatically. Changing unrelated verification history does not erase private history or arbitrarily revoke another role. Eligibility loss suppresses output immediately. Temporary restriction removal may restore the still-confirmed unchanged release using only current roles; explicit owner withdrawal/staff hide is a latch which reconciliation cannot undo. New/reapproved capabilities never appear unless release-selected and currently verified. New content or new selected media requires a new confirmation. Do not add publication values to C03 `profile.state`.

## 3. Public read, consistency, media and concurrency contracts

### One read policy

`public_professional(profile_uuid, at) -> PublicProfessionalDTO | None` is the authoritative marketplace reader. Require fresh Marketplace flag, effective nonhidden publication revision and current source-version/media/summary bindings, current C03 eligibility and at least one intersecting verified role. Recompute the intersection and current summaries at read time. Return no object on withdrawal, expiry, archival/deletion/restriction, missing identity, no current selected roles, missing binding or infrastructure failure. A repository outage is 503 with no content; invisible objects otherwise use uniform 404. No response or error reveals existence of a private profile.

Projection is an indexable copy of approved fields, not a second permission source. Stored binding digest/generation/next expiry are optimization/reconciliation data. Time is freshly sampled at the final read/release check; caller-supplied `at` is a trusted test/service boundary, never a browser parameter. Fresh counters do not replace timestamp checks. A role restriction filters only that role; identity/account failure hides the whole profile. A stale publication source version hides the whole revision until deliberately republished. An explicitly selected qualification whose revision changes cannot silently acquire a public replacement.

Release boundary: build/authorize the nonstreaming payload inside a bounded transaction and serialize/render before releasing required locks. Multi-owner reads acquire User anchors sorted by database identity before profile/child locks, then follow existing C03 order; never lock projection then User. Favorites/comparison composition locks caller and target owner anchors in this same order before account/target checks. Read media bytes outside database locks, then reauthorize exact copy/release/source generation at final buffered release under short locks. Do not hold domain locks across decoder, scanner or object-store calls. Tests define linearization: revocation committed before final release denies; a response already authorized/released before revocation cannot be recalled from the network/browser. No claim of retracting downloaded bytes or search-engine caches.

No public content cache/CDN/Service Worker response cache in C04. Send `Cache-Control: no-store` on profiles, result payloads, comparison, media and sitemap; eligible pages can still be indexable. Disable proxy/CDN stale serving and conditional 304 paths that bypass current authorization; do not use stale-while-revalidate. Static hashed assets retain normal caching. A later public-content cache requires an approved revocation-safe design.

### Separate public copies and safe delivery

`PublicAssetCopy` in assets has opaque public-copy UUID, validated source owner/subject/purpose, source processing and release revision, output checksum/MIME/dimensions, key in a distinct publication namespace/store, generation, state, lease and timestamps. It never changes source classification or private AssetDerivative purposes/ACLs. Sanitization can consume a currently authorized ready pixel derivative internally and re-encode into a new object; owner/staff preview endpoints and private derivative keys stay private. Public selection cannot name evidence purposes even if bytes appear innocuous. Use the existing isolated decoder and real scanner pipeline; new educational-image ingress uses the same private quarantine guarantees.

Creation: authorize and record pending generation → bounded scan/sanitize/copy outside locks → validate checksum/output metadata → lock/recheck owner/publication/source/current eligibility/generation → mark ready and activate only complete revision. A withdrawal/source change during I/O leaves the output unreferenced and inaccessible, queued for policy-controlled cleanup. Unique `(release_revision, purpose, source_asset, processing_version)` effects and lease/version fences handle duplicate/crashed workers. Never serve pending/quarantined output.

The publication namespace is separate but origin ACL remains nonanonymous; expose only an isolated public-media origin/gated proxy that calls current public authorization with a public-copy ID and buffers bounded JPEG/PNG. No shared cross-subdomain session cookie is needed for anonymous public authorization. Emit no bucket/key/source IDs, no permanent object URL or public presigned download. Nosniff, fixed content type, generic filename, no CORS credentials; external arbitrary image URLs/SVG/CSS are rejected. Deleting/hiding release denies the proxy immediately even if physical cleanup fails. Policy/record holds govern physical erasure, never ordinary public delivery. Disclose that copies already downloaded cannot be recalled.

### Refresh, reconciliation and flag behavior

New domain events: `professional.publication_changed` (`publication_uuid,user_uuid`), `professional.post_changed` (`post_uuid,user_uuid`), `marketplace.moderation_changed` (`moderation_uuid,user_uuid`); all UUID-only, exact aggregate binding, schema 1. Add audit/outbox enum and PostgreSQL function/CHECK support in new governance migrations. Existing account/profile/verification/asset/flag events invoke C04 effects through explicit composition, preserving C03 effects/results and delivery receipts. No feature-domain import is added to accounts/governance/assets. Stale events request re-evaluation of current state, never write their old snapshots. Existing already-sent C03 events are repaired by initial/due reconciliation rather than altering historical receipts.

`refresh_public_projection(profile_uuid, at) -> RefreshResult` locks anchors, reads current release/eligibility, upserts or tombstones current projection atomically and never generates a new consent. No public copy work under outbox locks; handlers record durable due work, and Celery scans execute I/O later. `reconcile_publications(at, batch_size=100) -> ReconcileResult` walks bounded UUID-keyset batches including active publications lacking a projection, dirty/stale projections, impending expiries and tombstones. Durable cursor/lease/due state supports crash recovery; unique per-generation effects prevent old jobs overwriting newer releases. Expiry always denies at request time regardless of scans.

Extend the existing private reconciliation schedule/worker installation (currently `config.c03_celery:app`) with C04 due scanning; do not add another scheduler process or change immutable C02 schedule fixtures. Proposed scan interval 30 seconds and batches ≤100 reuse C03 conventions; they are engineering defaults, not a visibility guarantee. Metrics expose finite backlog/oldest-age/failures/exhaustion and purge counts, never content. Retain existing eight-attempt bounded outbox policy. Exhaustion alerts and explicit audited operator retry do not bypass authorization; reconciliation remains safe while broker/Beat is down.

Marketplace false/missing/unavailable denies public pages, search, SEO/sitemap entries, public media, publication and favorite/comparison additions immediately. No history is deleted. Owner private preview/draft management and owner withdrawal/removal/clear remain available through private account-authorized routes; reconciliation/purge must continue with flag off. Re-enable still checks current eligibility and release state and never creates new publication. The professional-registration switch remains independent.

## 4. PostgreSQL search contract

`normalize_persian(value: str) -> str`: version `fa-search-v1`; NFKC, Arabic Yeh/Kaf → Persian ی/ک, Arabic/Persian digits → ASCII, remove Arabic combining marks/tatweel, ZWNJ/ZWJ → token separator, collapse whitespace and casefold Latin. Apply the same function to approved indexed text, query and string filter keys; preserve original presentation text. Do not conflate distinct cities/countries or transliterate arbitrary specialties. Test `كيان/کیان`, `۱۲/١٢/12`, diacritics, half-space/spaces, punctuation, mixed Latin, empty and control characters. Display-text validation continues to reject markup/control input independently.

Use PostgreSQL `simple` text-search configuration over normalized Persian tokens (no claim of a built-in Persian stemmer). Weighted `SearchVector`: A display name/specialty, B public summary title and broad city/region, C biography; only intentionally released text is indexed. GIN tsvector plus `pg_trgm` GIN normalized name/specialty lookup, and relational filter indexes. Use parameterized `SearchQuery(..., search_type='plain', config='simple')`; no user raw tsquery/SQL/regex. Trigram fallback applies for normalized query length ≥3 with threshold 0.3; full-text results rank ahead of trigram-only. Empty query browses current eligible publications; a nonempty query normalized to nothing returns validation error.

Order: match tier descending (FTS then trigram-only), `floor(ts_rank_cd*1000000)` descending, `floor(similarity*1000000)` descending, public profile UUID ascending. Empty query uses UUID ascending. Quantized scores and UUID form deterministic keyset order for a fixed dataset/query; no random, latest-update promotion, fabricated quality score or personalization. A live data change can reorder pages; cursors do not promise a historical snapshot. User chooses restart after expired/invalid cursor. Rendering factual labels (“specialty matches”, “online service”) derives only from actual criteria, not ranking percentages.

`SearchCriteria` fields: q ≤120 Unicode characters and ≤12 normalized tokens, role `coach|nutritionist` (omit means either eligible), mode `online|in_person`, paired optional country/region/city, ≤5 specialties, ≤5 language tags, optional integer min/max experience 0..80, sort `relevance` only, page_size 1..20. Unknown/duplicate/unsupported fields rejected; experience NULL does not match numeric criteria. Region/city/mode must match the same released active location tuple, not separate records; role uses current intersection, never declarations. Specialty/language selections are OR within each field and AND across fields; region/city are normalized exact matches, not substring. No unavailable criteria appear in schema/UI. Bound query-string bytes at 4096 and cursor at 2048.

`search_public_professionals(criteria, cursor, at) -> PublicPage` selects indexed candidates with coarse current-state prefilters, then fresh batched public authorization before any card/count/relevance label leaves the server. ≤100 candidates per request, ≤20 public results. No raw candidate totals/facets or private UUIDs in cursors. Cursor is signed and bound to normalized criteria, sort, normalization version, page size and 15-minute issue time; contains only the last returned public ordering key. If 100 candidates are consumed without proving the requested page boundary, return retryable `projection_refresh_required` (503, no partial private metadata), enqueue bounded reconciliation; do not claim an empty marketplace or emit a cursor containing an invisible row. Revalidation can suppress stale hits but cannot expose them; a new eligible publication may be temporarily undiscoverable until refresh. Direct eligible profile reads can build from current immutable release even when index lags; never construct from unsanitized private fields.

Proposed engineering abuse defaults: trusted-IP HMAC keyed 60 search requests/minute, account/session HMAC keyed 30 comparison writes/minute and account keyed 30 favorite writes/minute, bounded request bodies 16 KiB (uploads retain existing bounds); Redis atomic TTL quotas in a separate marketplace namespace using existing trusted proxy extraction. Do not change OTP quota semantics or store raw queries/IPs. Limiter failure denies expensive search/mutations with 503; 429 has bounded Retry-After. Cheap profile/SEO/media reads also have finite configured origin quotas (120/minute/IP) and existing server body/time limits. No new durable surveillance history or arbitrary per-filter database count. PostgreSQL statement timeout 2 seconds for search and lock timeout 1 second produce bounded 503, never a privacy fallback. Load tests in Task 10 validate defaults before release.
